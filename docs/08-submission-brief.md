## B1. What it is

Understudy is an incident-response agent that never tests a fix on production. When an
alert fires, it generates {{ candidate_count }} candidate remediations, forks
{{ candidate_count }} isolated replicas of production, mirrors live traffic into all of
them simultaneously, scores the candidates against a common rubric, and submits the winner
to a Z3-backed safety kernel that can veto it regardless of how well it performed. Between
incidents it runs the same machinery speculatively, building a playbook library of
remediations validated against failure modes that have not happened yet.

Five external integrations, all real: **GitHub** (deploy history and rollback targets),
**Kubernetes** (actuation surface for production and every twin), **Prometheus + Loki**
(observability signal), **PagerDuty** (trigger and escalation), **Slack** (reasoning
narrative). A **Datadog** free-tier adapter implements the same observability interface.

## B2. Architecture in one page

```
alert → context → N candidates → N forked twins ← live mirrored traffic
                                      ↓
                                 tournament (deterministic; LLM judge advisory)
                                      ↓
                            safety kernel (Z3, {{ proof_count }}/{{ invariant_count }} proof-backed)
                              ↓ PASS            ↓ VETO / UNCERTAIN / AMBIGUOUS
                        act on production    escalate with full comparative evidence
```

The design decision that distinguishes this from a testing product: rehearsal, arbitration
and formal verification all live inside the agent's runtime control loop and run at
incident cadence, rather than as an offline gate before deployment.

Full architecture: `docs/02-architecture.md`. Every design decision with its rejected
alternatives: `docs/01-decisions.md`.

## B5. Tournament efficiency, measured against a real counterfactual

For every run, after applying the winner to production and recording the outcome, we reset
the cluster, re-injected the identical scenario, and applied the **runner-up** to
production directly. Regret rate is therefore an observation, not an inference from the
twins' own scores — using twin scores to validate the tournament that trusts twin scores
would be circular.

Regret rate {{ regret.point }} [{{ regret.low }}, {{ regret.high }}], n = {{ regret.n }}.
{{ regret_commentary }}

Limitation: we compare the winner against the runner-up only, not all N−1 alternatives,
because counterfactual runs scale linearly in cost. The runner-up is the strongest rival, so
this is the tightest comparison available at fixed budget.

## B8. Known limitations

Stated because a reliability brief that lists none is not a reliability brief.

1. **The twins are not independent.** All {{ candidate_count }} are forked from the same
   snapshot and fed the same mirrored traffic. A defect in the twin infrastructure can make
   every candidate wrong in the same way. The fleet reduces the variance of a single bad
   guess; it does not close the fidelity gap. Our response is measurement (§B4) plus
   invariant K8, which refuses to clear any plan whose evidence is stale, thin, or built on
   a twin that dropped more than 5% of mirrored traffic.
2. **Twins start cold.** In-flight state and warm caches do not survive the fork. A 20
   second warm-up window is excluded from scoring; residual bias is unmeasured.
3. **Traffic is deterministic and synthetic.** Reproducibility of the evaluation required
   it. With organic traffic, drop ratios rise and the correlation interval widens.
4. **The corpus is a fixture.** {{ scenario_count }} scenarios on a four-service stack are
   not a sample of real incidents. Generated (shadow-discovered) scenarios are reported
   separately from seed scenarios so no metric is inflated by cases the system authored for
   itself.
5. **The action space is closed by construction**, not by proof. Safety rests on the closed
   enum of {{ action_count }} action types plus the invariants — never on the planner
   behaving. The LLM is outside the trusted base.
6. **Small n.** Every proportion here carries its interval for exactly this reason.
   {{ small_n_note }}
7. **Mirroring is application-layer**, implemented by a component we wrote, not by a
   service mesh. Trade-offs and rejected mesh options: ADR-012.
